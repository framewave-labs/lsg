# A2팀 기능명세서 — 인수인계본 v5.0
> 작성일: 2026-07-12 | 인수인계본 정리일: 2026-08-02 | 작성자: 이슬기 (PM)
> GeNova(A2팀 생성형 AI 통합 엔진)의 기능을 화면 단위로 정리한 문서다. 실제 배포 서비스(`kx-frontend-azure.vercel.app`)를 직접 조작해 확인한 화면 구조·옵션에, 개발 착수 전 설계 문서(v0.1~v0.8)에 있던 **기능 ID 체계·UI 세부 사양·입력 제약·비동기 상태 처리 원칙·에러 코드/처리·인수 조건·엣지 케이스를 항목 형식 그대로 빠짐없이** 합쳐서 다시 썼다. 실제 화면과 다르게 구현된 부분은 확인된 내용으로 교체했고, 화면까지는 확인했지만 세부 동작을 재확인하지 못한 부분은 설계 당시 사양을 그대로 실었다 — 어느 쪽인지는 각 항목에 표시했다.

## 1. 서비스 개요

GeNova는 방송 제작자를 위한 생성형 AI 통합 편집 도구다. 한국어 프롬프트만으로 캐릭터·배경 이미지, 캐릭터 시트, 짧은 영상을 만들고, 레퍼런스 이미지에서 프롬프트를 역으로 추출할 수 있다.

| 항목 | 내용 |
|------|------|
| 화면 구조 | 단일 페이지 + 기능별 화면(좌측 사이드바로 이동) |
| 인증 | 이메일 로그인 + Google OAuth 병행 (확인됨) |
| 이미지 생성 모델 | GPT Image 2.0 — OpenAI 직접 호출 (확인됨, 2026-07-28 QA에서 fal.ai 경유 아님을 재확인) |
| 영상 생성 모델 | Seedance 2.0 / Kling 3.0 — fal.ai 경유 (확인됨) |
| 프롬프트 보조·이미지 분석 | Claude Sonnet (역프롬프트 화면에는 "Claude Sonnet 5"로 구체 버전 표기, 확인됨) |
| 스토리지 | AWS (EC2 + S3) |
| 프런트엔드 배포 | Vercel — `kx-frontend-azure.vercel.app` |
| 백엔드 배포 | AWS — `kx-studio.duckdns.org` (확인된 API 베이스 URL) |
| UI 언어 | 한국어 단일 |
| 지원 환경 | 데스크톱 웹 기준 |

## 3. 공통 동작 규칙

### 3.1 API 공통 형식

```typescript
// 성공
{ success: true, data: { ... } }

// 실패
{ success: false, error: { code: string, message: string } }
```

`error.message`는 사용자에게 그대로 보여줄 수 있는 한국어 문장이며, 프런트는 이 값을 우선 표시한다. 아래는 실제 네트워크 요청에서 확인된 엔드포인트다(전체 API 목록은 아니며, 이번 검증 과정에서 관찰된 것만 정리).

| 엔드포인트 | 메서드 | 용도 |
|------|------|------|
| `/api/me/profile` | GET | 내 프로필 정보 조회 |
| `/api/auth/email/check?email=` | GET | 회원가입 1단계 — 이메일 확인 |
| `/api/generate/images/jobs/active` | GET | 진행 중인 이미지 생성 작업 확인 |
| `/api/generate/videos/jobs/active` | GET | 진행 중인 영상 생성 작업 확인 |
| `/api/media/files?type={IMAGE\|VIDEO}&page={n}&size={n}` | GET | 라이브러리 목록 조회 |
| `/api/media/images/{id}/download` | GET | 이미지 다운로드 |

이미지·영상 생성을 요청하는 POST 엔드포인트, 라이브러리 삭제(`DELETE`)·찜 토글(`PATCH`) 엔드포인트의 정확한 경로는 이번 검증에서 캡처하지 못했다. 아래는 설계 당시(v0.8) 정의됐던 이름이다(재확인 필요).

| 설계 당시 엔드포인트 | 용도 |
|------|------|
| `POST /auth/signup` | 회원가입 |
| `POST /auth/login` | 로그인 |
| `POST /auth/google` | Google OAuth 콜백 처리 |
| `POST /generate-image` | 이미지 생성 |
| `POST /generate-video` | 영상 생성 |
| `GET /video-status?id=` | 영상 생성 상태 폴링 |
| `GET /library` | 라이브러리 조회 |
| `PATCH /library/{id}/favorite` | 찜 토글 |
| `DELETE /library/{id}` | 라이브러리 항목 삭제 |
| `POST /reverse-prompt` | 역프롬프트 분석·추출 |
| `POST /reverse-prompt-generate` | 역프롬프트 결과로 이미지 재생성 |

### 3.2 에러 코드 표 (BE·FE 공통, 설계 당시 정의)

| 코드 | HTTP | 원인 | 사용자 표시 메시지 |
|------|------|------|------|
| `INVALID_INPUT` | 400 | 빈 프롬프트, 잘못된 파라미터 | "입력값을 확인해 주세요." |
| `AUTH_FAILED` | 401 | 이메일·비밀번호 불일치 | "이메일 또는 비밀번호를 확인해 주세요." |
| `SESSION_EXPIRED` | 401 | 세션·토큰 만료 | "로그인이 만료되었습니다. 다시 로그인해 주세요." |
| `DUPLICATE_EMAIL` | 409 | 회원가입 이메일 중복 | "이미 사용 중인 이메일입니다." |
| `FILE_TOO_LARGE` | 400 | 업로드 파일 10MB 초과 | "10MB 이하 파일만 업로드 가능합니다." |
| `UNSUPPORTED_FORMAT` | 400 | 지원하지 않는 파일 형식 | "jpg, png, webp 파일만 업로드 가능합니다." |
| `GENERATION_FAILED` | 500 | 이미지 생성 실패 | "이미지 생성에 실패했습니다. 다시 시도해 주세요." |
| `VIDEO_GENERATION_FAILED` | 500 | 영상 생성 실패 | "영상 생성에 실패했습니다. 다시 시도해 주세요." |
| `ANALYSIS_FAILED` | 500 | 역프롬프트 분석 실패 | "이미지 분석에 실패했습니다. 다시 시도해 주세요." |
| `TIMEOUT` | 504 | 생성 시간 초과 | "생성 시간이 초과되었습니다. 다시 시도해 주세요." |
| `API_LIMIT_EXCEEDED` | 429 | API 비용 한도 초과 | "현재 사용량 한도에 도달했습니다. 잠시 후 다시 시도해 주세요." |
| `STORAGE_FAILED` | 500 | 저장소 저장 실패 | "저장 중 오류가 발생했습니다. 다시 시도해 주세요." |
| `NOT_FOUND` | 404 | 존재하지 않거나 이미 삭제된 리소스 | "요청한 항목을 찾을 수 없습니다." |
| `UNKNOWN` | 500 | 그 외 오류 | "알 수 없는 오류가 발생했습니다. 다시 시도해 주세요." |

이번 검증에서 실제로 재현된 에러는 회원가입 1단계의 "이메일 확인에 실패했습니다. 다시 시도해주세요." 하나였다(5.1절 참고, 실제로는 503 서버 오류).

### 3.3 비동기 상태 처리 원칙 (설계 당시 정의)

이미지·영상 생성처럼 시간이 걸리는 모든 비동기 동작은 아래 세 상태를 반드시 구현하도록 설계되어 있었다.

| 상태 | UI 기준 |
|------|--------|
| **Loading** | 스피너 또는 스켈레톤 + 트리거 버튼 비활성화. 2초 이상 걸리는 작업은 진행 문구 병기 |
| **Error** | 한국어 에러 메시지 + [다시 시도] 버튼. 에러 코드는 콘솔 로그로만 기록 |
| **Empty** | 안내 문구 + 해당 기능 시작 CTA 버튼 |

이미지 생성 결과 영역, 영상 생성 상태 화면, 라이브러리 그리드에서 Loading·Empty 상태는 실제로 확인됨. Error 상태 화면까지는 재현하지 못했다.

### 3.4 중복 요청 방지 규칙 (설계 당시 정의)

- 생성·저장·삭제 등 쓰기 요청은 응답 수신 전까지 트리거 버튼을 비활성화한다
- 이미지·영상 생성은 화면당 동시 1건만 허용 — 진행 중 재요청 불가
- 폴링 중 화면 이탈 시 폴링은 중단되지만, 서버 측 생성 자체는 계속 진행된다(확인됨 — 8.4절)

### 3.5 생성·저장 공통 규칙 (확인됨)

- **생성이 완료되면 사용자 조작 없이 즉시 라이브러리에 자동 저장된다.** 별도의 [저장] 버튼은 없다.
- 재생성해도 이전 결과는 삭제되지 않고 라이브러리에 별개 항목으로 남는다.
- 예외: 역프롬프트로 "프롬프트를 추출"만 한 경우는 저장되지 않는다. [이 프롬프트로 생성하기]로 실제 이미지를 만들었을 때 그 결과 이미지만 저장된다 (9장 참고).

### 3.6 토스트·확인 모달 규칙 (설계 당시 정의)

| 상황 | UI |
|------|----|
| 성공 피드백 (저장·복사·변경 완료) | 토스트 3초 자동 닫힘 |
| 복구 불가 동작 (삭제·탈퇴) | 확인 모달 — [취소]가 기본 포커스, 확인 버튼은 위험색 |
| 실패 피드백 | 해당 영역 인라인 에러 메시지 |

**예외(확인됨)**: 내 프로필의 회원 탈퇴는 이 규칙과 달리 커스텀 모달이 아니라 브라우저 기본 확인창(`confirm()`)으로 구현되어 있다 (11장 참고).

### 3.7 세션 만료 처리 (설계 당시 정의)

어떤 API든 `SESSION_EXPIRED`(401)를 받으면 토스트를 띄운 뒤 로그인 화면으로 이동한다. 로그인 성공 시 홈 화면으로 이동한다(만료 직전 화면 복원은 지원하지 않음).

### 3.8 파일명 규칙 (다운로드, 설계 당시 정의)

| 대상 | 규칙 | 예시 |
|------|------|------|
| 이미지 | `image_{YYYYMMDD}_{HHmmss}.png` | `image_20260715_143012.png` |
| 영상 | `video_{YYYYMMDD}_{HHmmss}.mp4` | `video_20260716_101530.mp4` |

## 4. 사이드바 (전 화면 공통)

좌측에 고정된 사이드바로 모든 화면을 이동한다. (확인됨)

- 기본 상태는 아이콘만 보이는 축소형이며, **마우스를 올리면(hover) 확장**되어 각 메뉴의 라벨 텍스트와 로고 옆 "GeNova" 워드마크가 함께 나타난다.

- 하단에는 프로필 영역이 있다. hover로 펼치면 아바타 옆에 스튜디오 이름과 이메일이 표시된다.
  - 프로필 영역 클릭 → 내 프로필 화면으로 이동
  - 그 바로 아래 [로그아웃] 버튼 (hover로 펼쳤을 때만 노출) — 클릭 시 확인 모달 없이 즉시 세션이 종료되고 로그인 화면으로 이동한다(설계 당시 정의, 실제 클릭 결과는 재확인 필요)

## 5. 인증 — 로그인·회원가입

### 5.1 회원가입 (AUTH-001)

**회원가입은 단일 화면 폼이 아니라 이메일 → 다음 정보 순서로 진행되는 3단계 마법사다(확인됨)** (화면 우측 상단에 "1/3" 형태로 진행 표시).

**1단계 — 이메일 입력 (확인됨)**

| 항목 | 내용 |
|------|------|
| 화면 문구 | "이메일 입력" / "가입할 이메일을 입력하세요." |
| 입력 필드 | `example@kx.com` 형식 placeholder, HTML `type=email`, `required` |
| 클라이언트 제약 | `maxlength`·`minlength`·`pattern` 속성 없음 — 이메일 형식 검증은 서버 쪽에서 처리하는 것으로 보임 |
| API | `GET /api/auth/email/check?email={입력값}` |

**에러 처리 (확인됨)**

| 케이스 | 표시 | 비고 |
|--------|------|------|
| 이메일 확인 API 호출 | "이메일 확인에 실패했습니다. 다시 시도해주세요." | **현재 이 API가 503(서비스를 사용할 수 없음)을 반환하고 있어, 유효한 이메일(example.com, gmail.com 도메인 둘 다 테스트)을 넣어도 이 에러가 뜨며 다음 단계로 진행되지 않는다.** 입력값 문제가 아니라 백엔드 쪽 문제로 보인다 |

**2·3단계 — 설계 당시 예상 사양 (재확인 필요)**

위 503 문제 때문에 2·3단계는 이번 검증에서 진입하지 못했다. 아래는 회원가입이 "이메일·비밀번호·비밀번호 확인 3개 필드" 구조로 설계됐던 v0.1~v0.8 문서 내용이다.

**UI 구성 요소**

| 요소 | 사양 |
|------|------|
| 비밀번호 입력 | password 필드, 표시/숨김 토글 아이콘 |
| 비밀번호 확인 입력 | password 필드, 표시/숨김 토글 아이콘 |
| [가입하기] 버튼 | 필수 입력이 모두 채워지기 전까지 비활성화 |

**입력 필드 제약**

| 필드 | 필수 | 제약 |
|------|------|------|
| 이메일 | ✅ | 이메일 형식, 최대 254자, 앞뒤 공백 자동 제거 |
| 비밀번호 | ✅ | 8자 이상, 최대 64자 |
| 비밀번호 확인 | ✅ | 비밀번호와 정확히 일치 |

**시스템 동작**
1. 클라이언트 검증 통과 확인 (형식·길이·일치)
2. `POST /auth/signup`(정확한 경로 미확인) 호출 — 요청 중 버튼 비활성화 + 스피너
3. 서버에서 이메일 중복 확인
4. 계정 생성 완료 → "가입이 완료되었습니다" 토스트 → 로그인 화면으로 이동
5. 실패 시 해당 필드 하단 인라인 에러 표시

**에러 처리 (설계 당시 사양)**

| 케이스 | 코드 | 표시 |
|--------|------|------|
| 이메일 형식 오류 | `INVALID_INPUT` | "올바른 이메일 형식을 입력해주세요" |
| 비밀번호 8자 미만 | `INVALID_INPUT` | "비밀번호는 8자 이상이어야 합니다" |
| 비밀번호 불일치 | `INVALID_INPUT` | "비밀번호가 일치하지 않습니다" |
| 중복 이메일 | `DUPLICATE_EMAIL` | "이미 사용 중인 이메일입니다" |
| 서버 오류 | `UNKNOWN` | 공통 메시지 |

**인수 조건 (설계 당시 사양)**
- [ ] 유효한 이메일·비밀번호(8자 이상)·일치하는 확인값 입력 시 계정이 생성된다
- [ ] 가입 완료 후 로그인 화면으로 이동한다
- [ ] 중복 이메일로 가입 시도 시 에러 메시지가 표시되고 계정이 생성되지 않는다
- [ ] 필수값 미입력 상태에서는 [가입하기] 버튼이 비활성화된다
- [ ] 요청 중 [가입하기]를 연타해도 요청이 1회만 발생한다

**엣지 케이스 (설계 당시 사양)**
- 이미 로그인된 상태에서 회원가입 화면 접근 → 홈 화면으로 리다이렉트
- 비밀번호에 공백만 8자 입력 시 그대로 허용할지 여부는 BE 협의 필요했던 사항(결론 미확인)

### 5.2 로그인 (AUTH-002)

이메일/비밀번호 로그인과 **"구글 계정으로 시작하기"** 버튼을 함께 제공한다(확인됨). 화면 배경에 랜덤하게 바뀌는 인물 사진과 "다시 오신 걸 환영해요" 카피가 있다(확인됨).

**UI 구성 요소 (설계 당시 사양)**

| 요소 | 사양 |
|------|------|
| 이메일 입력 | text 필드 |
| 비밀번호 입력 | password 필드, 표시/숨김 토글 |
| [로그인] 버튼 | 두 필드 모두 입력 전 비활성화 |

**시스템 동작**
1. 로그인 API 호출 — 요청 중 버튼 비활성화 + 스피너
2. 인증 성공 → 세션·토큰 발급 → 홈 화면으로 이동 (확인됨)
3. 인증 실패 → 폼 상단 인라인 에러

**에러 처리**

| 케이스 | 코드 | 표시 |
|--------|------|------|
| 이메일·비밀번호 불일치 | `AUTH_FAILED` | "이메일 또는 비밀번호를 확인해주세요" |
| 미가입 이메일 | `AUTH_FAILED` | 동일 메시지 — 보안상 가입 여부 구분하지 않음(설계 당시 사양, 문구까지 일치하는지는 재확인 필요) |
| 서버 오류 | `UNKNOWN` | 공통 메시지 |

**인수 조건**
- [x] 올바른 계정 정보 입력 시 홈 화면으로 이동한다 (확인됨)
- [ ] 실패 메시지는 미가입·비밀번호 오류를 구분하지 않는다 (설계 당시 사양, 재확인 필요)
- [x] 로그인 상태에서 새로고침해도 세션이 유지된다 (확인됨)
- [ ] 세션 만료 후 API 호출 시 3.7절 공통 처리가 동작한다 (재확인 필요)

**엣지 케이스 (설계 당시 사양)**
- 이미 로그인된 상태에서 로그인 화면 접근 → 홈 화면으로 리다이렉트
- 연속 로그인 실패 제한(예: 5회)은 이번 범위 제외로 설계됨

### 5.3 Google 로그인 (AUTH-002B)

**시스템 동작**
1. "구글 계정으로 시작하기" 버튼 클릭 → Google 동의 화면(`accounts.google.com/o/oauth2/v2/auth`)으로 이동 (확인됨 — 콜백 주소는 `kx-studio.duckdns.org/login/oauth2/code/google`)
2. 인증 성공 → 콜백으로 획득한 이메일 기준 계정 조회 (설계 당시 사양)
3. 기존 계정 없음 → 신규 계정 자동 생성 후 바로 로그인 처리(설계 당시 사양)
4. 기존 계정 있음(이메일 방식으로 이미 가입됨) → 계정 연결 정책은 설계 당시에도 미정이었고 이번에도 재확인하지 못했다

**계정 속성 (Google 로그인 사용자, 설계 당시 사양)**
- 비밀번호 없음 → 프로필 화면에 비밀번호 변경 항목 비노출로 설계됨. 다만 실제 프로필 화면(11장)에는 로그인 방식과 무관하게 비밀번호 변경 항목 자체가 없다
- Google 계정 연결 상태는 해제 불가하도록 설계됨(계정 잠김 방지)

**에러 처리**

| 케이스 | 코드 | 표시 |
|--------|------|------|
| OAuth 인증 실패·취소 | `AUTH_FAILED` | "Google 로그인에 실패했습니다. 다시 시도해주세요" |
| 이메일 계정과 충돌 | 미정 | 설계 당시에도 확정되지 않음 |

**인수 조건 (설계 당시 사양)**
- [ ] "구글 계정으로 시작하기" 클릭 시 최초 사용자는 별도 회원가입 절차 없이 계정이 생성되고 로그인된다
- [ ] Google 로그인 사용자의 내 프로필 화면에는 비밀번호 변경 항목이 노출되지 않는다

## 7. 이미지 생성

모델은 **GPT Image 2.0으로 고정**되어 있다(확인됨). 상단 "유형" 탭으로 세 가지 생성 방식을 선택한다.

### 7.1 유형 — 캐릭터 / 배경 / 캐릭터시트 (M001, 확인됨)

| 유형 | 진입 방식 | 각도 옵션 | 비율 기본값 | 결과물 |
|------|---------|---------|-----------|--------|
| 캐릭터 | 프롬프트 입력 후 바로 생성 | 단일 / 다각도 | 1:1 | 단일: 캐릭터 이미지 1장 · 다각도: 정면·측면·후면 세트로 추정(재확인 필요) |
| 배경 | 프롬프트 입력 후 바로 생성 | (없음) | 1:1 | 배경 이미지 1장 |
| 캐릭터시트 | **[+ 캐릭터 만들기]** 버튼을 먼저 눌러 진입 | (없음) | 16:9 | 턴어라운드+표정+소품+컬러 팔레트 포함 캐릭터 시트로 추정(진입 이후 상세 플로우는 재확인 필요) |

캐릭터시트 진입 버튼([+ 캐릭터 만들기])을 누른 뒤의 상세 입력 방식은, 설계 당시 문서 기준으로는 **자유 텍스트 입력**(PART1 서술+PART2 JSON 구조)과 **속성 선택 사이드바**(파트1 캐릭터 기본 / 파트2 아트 스타일·세계관 / 파트3 헤어 / 파트4 얼굴 / 파트5 의상·악세서리, 컬러 항목은 컬러 팔레트+헥스코드 직접 입력) 두 가지를 모두 지원하도록 되어 있었다. 이 상세 화면 구성이 실제로 그대로 남아있는지는 이번 검증에서 확인하지 못했다.

### 7.2 공통 옵션 (확인됨)

| 옵션 | 값 |
|------|-----|
| 비율 | 1:1 · 16:9 · 9:16 (4:3은 지원하지 않음) |
| 품질 | 표준(Standard) · 4K |
| 수량 | 1장 이상 (카운터로 조절) |
| 레퍼런스 이미지 | 최대 8장 첨부 가능 (설계 문서엔 없던 기능) |
| AI 프롬프트 변환 | On/Off 토글, 기본값 Off. On 시 입력한 한국어를 백그라운드에서 영어 프롬프트로 변환한 뒤 생성 요청(변환 결과 미리보기는 없음). hover 보조 문구: "입력한 내용을 이미지 생성용 영어 프롬프트로 다듬어드려요" |
| 프롬프트 입력창 | textarea, 자동 높이 확장. 설계 당시 제약: 1자 이상(공백만 입력 시 빈값 처리), 최대 2,000자(GPT Image 2 API 자체 한도는 32,000자) |

### 7.3 이미지 생성 호출 (M002)

**시스템 동작 (설계 당시 사양, 흐름 자체는 확인됨)**
1. 클라이언트 검증: 빈값·공백만·최대 길이 초과 차단
2. AI 프롬프트 변환 토글 On 시, 서버에서 Claude Sonnet 변환 실행 후 변환된 영어 프롬프트로 GPT Image 2 호출
3. 생성 요청 — 버튼 비활성화 + 결과 영역 Loading (확인됨)
4. 클라이언트 타임아웃 60초로 설계됨
5. 성공 → 결과 영역에 이미지 표시 (확인됨)

**에러 처리**

| 케이스 | 코드 | UI 동작 |
|--------|------|--------|
| 프롬프트 빈값 | — (클라이언트 차단) | 버튼 비활성 + 입력창 하단 안내 |
| 생성 실패 | `GENERATION_FAILED` | 결과 영역 에러 상태 + [다시 시도] |
| 60초 타임아웃 | `TIMEOUT` | 동일 |
| 비용 한도 초과 | `API_LIMIT_EXCEEDED` | 에러 메시지 노출, [다시 시도] 비노출로 설계됨 |

**인수 조건**
- [x] 캐릭터/배경/캐릭터시트 유형에서 프롬프트 입력 후 [생성] 클릭 시 이미지가 생성된다 (확인됨)
- [x] AI 프롬프트 변환 토글 On 상태에서 생성 시 영어 프롬프트 미리보기 없이 바로 생성이 진행된다 (확인됨)
- [x] 생성 중 로딩 상태가 표시되고 버튼은 비활성화된다 (확인됨)
- [x] 선택한 비율이 생성 결과에 반영된다 (확인됨)
- [ ] 빈 프롬프트로는 생성 요청이 발생하지 않는다 (재확인 필요)
- [ ] 실패 시 에러 메시지와 [다시 시도] 버튼이 표시된다 (재확인 필요)

**엣지 케이스 (설계 당시 사양)**
- 생성 중 화면 이탈 시 요청 결과는 폐기되도록 설계됨(재진입 시 복원 없음)
- 이미지 로드 실패(URL 만료 등) 시 대체 이미지 + [다시 시도]로 설계됨

### 7.4 생성 결과 표시·자동 저장 (M003, M004)

생성이 끝나면 결과 영역에 이미지가 원본 비율로 표시되고, 라이브러리에도 즉시 자동 저장된다(확인됨). 결과를 클릭하면 라이브러리 상세보기와 동일한 **우측 패널**이 열리며, 아래 버튼을 제공한다(확인됨).

- [재편집]
- [동영상 만들기] — 이 이미지를 가지고 영상 생성 화면으로 이동(이미지가 프리필되는 것으로 추정)
- [다운로드] — PNG 원본, 파일명 규칙은 3.8절 참고
- [삭제]

**재생성**: [재생성]을 누르면 기존 프롬프트·옵션이 유지된 채로 다시 생성을 요청한다(확인됨). 새 결과는 별도의 라이브러리 항목으로 저장되며, 기존 결과는 삭제되지 않는다.

**저장 실패 시 에러 처리 (설계 당시 사양)**: 생성 자체는 성공했지만 저장 단계에서 실패하면 "이미지 생성은 완료됐지만 저장 중 문제가 발생했습니다" 인라인 메시지와 [다시 저장] 버튼이 뜨도록 설계되어 있었다(코드: `STORAGE_FAILED`).

**인수 조건 (설계 당시 사양)**
- [x] 이미지 생성이 완료되면 사용자 조작 없이 자동으로 라이브러리에 저장된다 (확인됨)
- [x] 별도의 [저장] 버튼이 존재하지 않는다 (확인됨)
- [ ] 저장된 항목이 라이브러리 최신순 맨 앞에 표시된다 (재확인 필요)
- [x] 재생성해도 이전 결과가 삭제되지 않고 라이브러리에 별개 항목으로 남아있다 (확인됨)

### 7.5 이미지 다운로드 (M006)

**시스템 동작 (설계 당시 사양)**
1. 클릭 시 PNG 원본을 브라우저 다운로드로 저장 — 파일명 규칙 3.8절
2. 실패 시 "다운로드에 실패했습니다. 다시 시도해주세요" 인라인 표시

**인수 조건 (설계 당시 사양)**
- [ ] 다운로드된 파일이 원본 해상도의 PNG로 저장된다
- [ ] 파일명이 3.8절 규칙을 따른다

## 8. 영상 생성

모델을 **Seedance 2.0 / Kling 3.0** 중에서 고르며, 어떤 모델을 선택하느냐에 따라 아래 옵션 전체가 달라진다(확인됨).

### 8.1 모델별 옵션 (확인됨)

**Seedance 2.0**

| 옵션 | 값 |
|------|-----|
| 길이 | 4초 · 5초(기본) · 8초 · 10초 · 15초 · 자동 |
| 비율 | 16:9·1376×768(기본) · 9:16·768×1376 · 1:1·1024×1024 · 21:9 · 4:3 · 3:4 · 자동 |
| 품질 | 고화질 1920×1080(기본) · 표준 1280×720 · 480p · 4K |
| 레퍼런스 이미지 | 최대 9장 |

**Kling 3.0**

| 옵션 | 값 |
|------|-----|
| 길이 | 3초 · 4초 · 5초(기본) · 8초 · 10초 · 15초 |
| 비율 | 16:9·1376×768(기본) · 9:16·768×1376 · 1:1·1024×1024 |
| 품질 | 별도 선택 옵션 없음 (12장 참고 — 회귀 여부 재확인 필요) |
| 레퍼런스 이미지 | 최대 4장 |

두 모델 다 실사용 가능한 정식 옵션이며, 어느 한쪽이 "테스트 전용"으로 제한되어 있지는 않다.

### 8.2 입력 (A002)

- **스토리보드 이미지** (필수, 1장) — 미리 준비한 스토리보드 이미지를 업로드한다. 설계 당시엔 "3x3 그리드 이미지 업로드"라는 이름으로, Kling 3.0 I2V 모델 특성상 그리드 이미지가 첫 프레임으로 그대로 사용돼 노출·순서 오류가 나는 문제가 보고된 적 있다. 지금은 "스토리보드" 업로드로 이름과 UI가 바뀌었고, 이번 검증 범위(업로드 자체)에서는 문제가 재현되지 않았다.
- **레퍼런스 이미지** (선택) — 스토리보드와 별개 슬롯. 최대 개수는 모델에 따라 다름(8.1절 참고)
- 프롬프트 입력창 — 설계 당시 제약: 1자 이상, 최대 2,000자

**오디오**: 설계 당시엔 "영상에 오디오 포함 필수"였고(Kling은 오디오 옵션 On 시 무음 대비 약 1.5배 과금, Seedance는 오디오 기본 포함으로 추가 과금 없음), UI에 별도 토글을 둘지 항상 켜둘지는 미정이었다. 이번 검증에서 화면에 별도 오디오 토글은 보이지 않았지만, 실제로 오디오가 항상 포함되는지는 재확인이 필요하다.

**입력 필드 제약 (설계 당시 사양)**

| 필드 | 필수 | 비고 |
|------|------|------|
| 프롬프트 | ✅ | 1자 이상, 최대 2,000자 |
| 스토리보드 이미지 | ✅ | jpg·png, 10MB 이하로 설계됨 |
| 모델 | ✅ | 기본값 설계 당시 kling-3 → 실제는 seedance 2.0 기본 노출(확인됨, 정정) |

**에러 처리**

| 케이스 | 코드 | UI 동작 |
|--------|------|--------|
| 프롬프트 빈값 | — | 버튼 비활성화 |
| 제출 실패 | `VIDEO_GENERATION_FAILED` | "영상 생성 요청에 실패했습니다. 다시 시도해주세요" + 입력값 유지 |
| 비용 한도 초과 | `API_LIMIT_EXCEEDED` | 공통 메시지, [다시 시도] 비노출로 설계됨 |

### 8.3 생성 상태 (A003)

생성 요청 후 아래 상태를 거치도록 설계되어 있다.

**폴링 규칙 (설계 당시 사양)**

| 항목 | 기준 |
|------|------|
| 간격 | 5초 |
| 최대 횟수 | 120회 (10분) — 초과 시 클라이언트 타임아웃 |
| 폴링 요청 실패 | 3회 연속 실패 시 에러 상태 전환 |
| 화면 이탈 | 폴링 중단. 생성 자체는 서버에서 계속 진행(확인됨) |

**상태별 UI**

| 상태 | 사용자 표시 |
|------|-----------|
| 대기 중(IN_QUEUE) | "대기 중입니다. 잠시만 기다려주세요." |
| 진행 중(IN_PROGRESS) | "영상을 생성하고 있습니다…" (프로그레스 바) |
| 완료(COMPLETED) | 결과 화면으로 전환 |
| 실패(ERROR) | "영상 생성에 실패했습니다. 다시 시도해주세요" |

**에러 처리**

| 케이스 | 코드 | UI 동작 |
|--------|------|--------|
| 10분 타임아웃 | `TIMEOUT` | "생성 시간이 초과됐습니다. 다시 시도해주세요" + [다시 시도] — 새 요청으로 처음부터 재시작 |
| ERROR 상태 수신 | `VIDEO_GENERATION_FAILED` | 위와 동일 흐름 |

**인수 조건 (설계 당시 사양)**
- [ ] 생성 요청 후 "대기 중 → 생성 중 → 완료" 상태가 순서대로 표시된다
- [x] 완료 시 결과 화면으로 자동 전환된다 (확인됨)
- [ ] 10분 초과 시 타임아웃 에러와 [다시 시도]가 표시된다
- [ ] 일시적 폴링 실패(1~2회)로는 에러 상태로 전환되지 않는다

### 8.4 생성 결과 표시 (A004)

생성이 끝나면 결과 영상이 표시되고 라이브러리에 자동 저장된다(확인됨). 결과를 클릭하면 라이브러리 상세보기와 동일한 **풀스크린 모달**이 열리며, 아래 정보와 버튼을 제공한다(확인됨).

- 찜하기(하트) · 공유 아이콘 (모달 상단)
- 사용한 프롬프트 (전체 보기 펼치기 / 복사)
- 모델·품질·비율·생성일자·작업 ID
- [재편집] · [다운로드] (MP4 원본)

**엣지 케이스 (설계 당시 사양)**
- 영상 URL 로드 실패 시 대체 UI + [다시 시도]로 설계됨
- 화면 이탈 후에도 서버 측 생성이 완료되면 자동 저장은 그대로 진행됨 — 저장을 위해 화면에 머무를 필요 없음(확인됨)

### 8.5 영상 재생성 (A005)

**시스템 동작**
1. [재생성] 클릭 → 기존 프롬프트·옵션이 채워진 입력 화면으로 복귀
2. 그대로 재요청하거나 프롬프트·옵션 수정 후 요청
3. 새 요청으로 재진입
4. 새 결과는 별도의 라이브러리 항목으로 저장된다 — 기존 결과는 삭제되지 않는다(확인됨)

**인수 조건 (설계 당시 사양)**
- [ ] [재생성] 클릭 시 기존 입력값이 유지된 상태로 수정 가능하다
- [ ] 재생성 요청이 새 요청으로 처리된다(기존 요청과 독립)
- [x] 재생성해도 이전 영상 결과가 삭제되지 않고 라이브러리에 별개 항목으로 남아있다 (확인됨)

## 9. 역프롬프트

레퍼런스 이미지를 분석해 그 이미지를 재현할 수 있는 프롬프트를 추출하는 기능이다.

| 항목 | 내용 |
|------|------|
| 분석 모델 | Claude Sonnet 5 (멀티모달, 확인됨) |
| 비율 | auto(기본) · 1:1 · 16:9 · 9:16 (확인됨) |
| 업로드 | 이미지 1장. 설계 당시 파일 제약: jpg·png·webp, 10MB 이하 |

### 9.1 이미지 업로드 (S001)

**UI 구성 요소 (설계 당시 사양)**

| 요소 | 사양 |
|------|------|
| 업로드 영역 | 드래그앤드롭 + 클릭 파일 선택 겸용 |
| 파일 제약 안내 | "jpg, png, webp · 10MB 이하" 상시 노출 |
| [프롬프트 생성] 버튼 | 유효한 파일 업로드 전 비활성화 |

**에러 처리 (설계 당시 사양)**

| 케이스 | 코드 | 표시 |
|--------|------|------|
| 미지원 형식 | `UNSUPPORTED_FORMAT` | "jpg, png, webp 파일만 업로드 가능합니다" |
| 10MB 초과 | `FILE_TOO_LARGE` | "10MB 이하 파일만 업로드 가능합니다" |

### 9.2 이미지 분석·프롬프트 추출 (S002)

1. 이미지를 업로드하고 [프롬프트 생성]을 누른다 (설계 당시 버튼명은 "[프롬프트 추출]", 확인됨: 실제 라벨은 "프롬프트 생성")
2. "제안된 프롬프트" 패널에 추출된 프롬프트가 표시된다 (확인됨)

**분석 결과 태그(설계 당시 사양, 재확인 필요)**: 추출 시 스타일·조명·구도·렌즈·색감·분위기 6개 항목을 태그 칩 형태로 함께 보여주도록 설계되어 있었다. 이번 검증에서는 비용 문제로 실제 추출을 실행하지 않아 이 태그들이 지금도 화면에 노출되는지 확인하지 못했다.

**에러 처리 (설계 당시 사양)**

| 케이스 | 코드 | UI 동작 |
|--------|------|--------|
| 분석 실패 | `ANALYSIS_FAILED` | "이미지 분석에 실패했습니다. 다시 시도해주세요" + [다시 시도] |
| 타임아웃(60초) | `TIMEOUT` | 동일 |

**인수 조건 (설계 당시 사양)**
- [ ] 업로드한 이미지에서 스타일·조명·구도·렌즈·색감·분위기 6개 항목이 추출된다
- [ ] 추출된 영문 프롬프트가 80단어 이하로 표시된다
- [x] [복사] 클릭 시 프롬프트가 클립보드에 복사된다 (확인됨 — 아이콘 존재)

### 9.3 결과 화면 — 수정·재생성 연결 (S003, S004)

**결과 화면 구조가 설계 문서와 다르다(확인됨) — 중요**

- 결과에는 **[복사] 아이콘**과 **더보기(⋮) 아이콘**, 두 개만 우선 노출된다. 설계 문서처럼 프롬프트 에디터가 바로 펼쳐져 있는 게 아니라, 더보기 아이콘을 눌러야 **[수정]** / **[이 프롬프트로 생성하기]** 두 버튼이 나오는 구조다.
- **[수정]** — 누르면 프롬프트 텍스트뿐 아니라 **비율도 함께 수정 가능** (설계 문서는 프롬프트 텍스트만 언급, 비율 수정은 없었음)
- **[이 프롬프트로 생성하기]** — 해당 프롬프트로 바로 이미지 생성 실행 (설계 당시 버튼명 "[이 프롬프트로 이미지 생성]"과 동일 기능으로 보임)
- **역프롬프트로 추출된 프롬프트 자체는 라이브러리에 저장되지 않는다.** 설계 문서는 "생성과 동시에 자동 저장"이라 했는데, 실제로는 **[이 프롬프트로 생성하기]를 눌러 이미지가 실제로 생성된 시점에만** 그 결과 이미지가 라이브러리에 저장되는 것으로 보인다.

**에러 처리 (설계 당시 사양)**

| 케이스 | 코드 | UI 동작 |
|--------|------|--------|
| 생성 실패 | `GENERATION_FAILED` | 결과 영역 에러 상태 + [다시 시도] |

**인수 조건**
- [x] [이 프롬프트로 생성하기] 클릭 시 화면 전환 없이 같은 페이지에서 이미지가 생성되는 것으로 추정 (재확인 필요 — 실제 실행은 안 해봄)
- [ ] 생성이 완료되면 별도 조작 없이 라이브러리에 자동 반영된다 (재확인 필요)
- [ ] 업로드 → 추출 → 수정 → 재생성까지 5분 이내에 완료 가능하다 (설계 당시 목표치, 재확인 필요)

- [원본으로 되돌리기]로 수정 내용을 추출 시점으로 되돌릴 수 있도록 설계됨 — 실제 존재 여부 재확인 필요

## 10. 라이브러리

생성한 모든 이미지·영상이 모이는 화면이다.

| 구성 | 옵션 |
|------|------|
| 상단 세그먼트 | 내 작업 · 찜한 목록 (확인됨) |
| 필터 탭 | 전체 · 이미지 · 영상 (확인됨) |
| 정렬 | 최신순(기본) · 오래된순 (확인됨) |

**조회 API (확인됨)**: `GET /api/media/files?type={IMAGE|VIDEO}&page={n}&size={n}`

**시스템 동작 (설계 당시 사양)**
1. 화면 진입 시 목록 API 호출
2. 필터 탭 전환 시 해당 타입으로 재조회
3. 찜한 목록 세그먼트 선택 시 재조회
4. 더 있으면 [더보기] 노출 → 클릭 시 다음 페이지 append

**인수 조건**
- [x] 저장된 이미지·영상이 최신순으로 표시된다 (확인됨)
- [x] 필터 탭으로 타입별 조회가 가능하다 (확인됨)
- [ ] 20개 초과 시 추가 로드가 동작한다 (재확인 필요)
- [ ] 항목이 없으면 빈 상태 UI와 생성 시작 안내가 표시된다 (재확인 필요)

### 10.1 상세보기

항목을 클릭하면 상세보기가 열리는데, **타입에 따라 형태가 다르다(확인됨).**

- **이미지** — 우측 고정 패널. 그리드 화면은 그대로 보이는 채로 옆에 펼쳐진다.
  - [재편집] · [동영상 만들기] · [다운로드] · [삭제]
- **영상** — 풀스크린 모달. 그리드 화면을 가리고 전체 화면으로 뜬다.
  - @핸들(예: `@my_studio`) · 찜하기(하트) · 공유 · 닫기
  - 사용한 프롬프트 (전체 보기 / 복사)
  - 모델·품질·비율·생성일자·작업 ID
  - [재편집] · [다운로드]

이미지·영상 생성 화면에서 방금 만든 결과를 클릭했을 때도 이 상세보기와 동일한 UI가 뜬다(확인됨).

**다운로드 API (확인됨)**: `GET /api/media/images/{id}/download`

### 10.2 삭제 (설계 당시 사양)

**시스템 동작**
1. [삭제] 클릭 → 확인 모달: "삭제하면 복구할 수 없습니다. 삭제하시겠습니까?" — [취소](기본 포커스) / [삭제]
2. 확인 → 삭제 API 호출 — 요청 중 버튼 비활성화
3. 성공 → 팝업 닫힘 + 그리드에서 즉시 제거 + "삭제되었습니다" 토스트
4. 실패 → 확인 모달 내 인라인 에러 + 재시도 가능

**에러 처리**

| 케이스 | 코드 | HTTP |
|--------|------|------|
| 존재하지 않거나 이미 삭제된 항목 | `NOT_FOUND` | 404 |
| 예상치 못한 서버 오류 | `UNKNOWN` | 500 |

**인수 조건**
- [x] 항목 클릭 시 상세보기가 열리고 프롬프트·메타 정보가 표시된다 (확인됨)
- [ ] 상세보기에서 다운로드가 동작한다 (재확인 필요)
- [ ] 삭제는 확인 모달을 거쳐야만 실행된다 (재확인 필요 — 이번 검증에서 실제 삭제는 실행하지 않음)
- [ ] 삭제 후 그리드에 즉시 반영된다 (재확인 필요)

### 10.3 찜하기 (설계 당시 사양)

하트 아이콘 클릭 시 즉시 상태가 바뀌고 그리드·찜한 목록에도 반영되도록 설계되어 있었다.

## 11. 내 프로필

사이드바 하단 프로필 영역을 클릭하면 진입한다(확인됨: `GET /api/me/profile`). 세 개의 카드로 구성된다.

### 프로필 카드 (AUTH-003)
- 프로필 이미지 (원형, [이미지 변경] 버튼)
- 스튜디오 이름 (텍스트 입력 + [저장])
- 이메일 (표시만, 수정 불가)

설계 당시엔 이 필드가 "닉네임"이었고, 로그인 방식 뱃지("일반"/"Google")와 가입일도 함께 표시하도록 되어 있었다. 실제 화면에는 "스튜디오 이름"이라는 이름으로 바뀌어 있고, 로그인 방식 뱃지와 가입일은 없다.

### 로그인 & 보안 (AUTH-004, 설계 당시 사양)

설계 문서는 일반 가입자에게 비밀번호 변경(현재 비밀번호/새 비밀번호/새 비밀번호 확인, 8자 이상 64자 이하)을, Google 로그인 사용자에게는 계정 연결 상태(해제 불가)를 보여주도록 계획했다. **실제 화면에는 이 섹션 자체가 없다(확인됨).**

### 활동 카드
- "내 생성 이력" 안내 문구 + [라이브러리로 이동] 버튼
- 별도의 통계·수치 표시는 없다 (설계 당시에도 크레딧/사용량 표시는 범위 제외로 명시되어 있었음)

### 위험 구역 (Account Deletion) — 회원 탈퇴 (AUTH-006)
- 회원 탈퇴 안내 문구 + [계정 삭제] 버튼
- 클릭 시 **브라우저 기본 확인창**(취소/확인)이 뜨며, 확인하면 계정과 라이브러리의 모든 생성물이 즉시 영구 삭제된다(확인됨)

**설계 당시 사양과의 차이**: 설계 문서는 이 확인 단계를 "계정이 영구적으로 삭제됩니다" 안내와 삭제 항목 체크리스트(모든 생성물 접근 권한 / 라이브러리 저장 콘텐츠 / 저장된 설정), "이해했습니다" 체크박스를 체크해야 [계정 삭제하기] 버튼이 활성화되는 커스텀 모달로 계획했다. 실제로는 그런 커스텀 디자인 없이 브라우저 기본 확인창으로 구현되어 있다 — 애초에 커스텀 디자인이 적용된 적 없는 상태로, 그 자체가 문제는 아니다.

**시스템 동작 (설계 당시 사양)**
1. [회원 탈퇴] 클릭 → 확인창 노출
2. 확인 → 계정 및 라이브러리 생성물 즉시 삭제
3. 탈퇴 완료 → 세션 종료 → 로그인 화면 이동 + 완료 토스트

**인수 조건 (설계 당시 사양)**
- [ ] 확인창에서 취소하면 탈퇴가 진행되지 않는다
- [ ] 확인하면 계정과 라이브러리 생성물이 즉시 삭제된다
- [ ] 탈퇴 완료 후 로그인 화면으로 이동한다

**이번 범위에서 제외된 것으로 확인된 항목 (설계 당시에도 제외로 명시됨)**
- 크레딧/사용량 표시
- 내 생성 이력/라이브러리 바로가기를 프로필 화면 안에 별도로 두는 것 (사이드 메뉴와 중복)
- 생성 완료 알림 토글, 세션·기기 관리, 언어·테마 설정

## 12. 확인되지 않은 사항

인수인계 시점까지 아래 항목은 직접 확인하지 못한 채로 남아있다. 후속 담당자가 실제 서비스나 코드베이스로 판단이 필요하다.

- **회원가입 2·3단계 화면** — 이메일 확인 API(`/api/auth/email/check`)가 503을 반환하고 있어 진행 자체가 막혀있다
- 캐릭터시트 유형에서 [+ 캐릭터 만들기] 진입 이후의 상세 입력 화면(자유 텍스트 vs 속성 선택 사이드바 구성)
- Kling 3.0에 품질 선택 옵션이 없는 것이 원래 의도인지, 이후에 빠진 것인지
- 라이브러리 찜하기(하트) 아이콘이 이미지 상세 패널에도 있는지 (영상 모달에는 있음을 확인)
- 라이브러리 상세보기가 이미지=패널, 영상=모달로 다른 것이 의도된 설계인지
- 영상 생성에서 오디오가 항상 포함되는지, 별도 켜고 끄는 옵션이 있는지
- 역프롬프트 결과에 스타일·조명·구도·렌즈·색감·분위기 분석 태그가 별도로 표시되는지 (비용 문제로 실제 추출을 실행해보지 않음)
- 라이브러리에 노출되는 `@my_studio` 형태의 핸들이 "스튜디오 이름"과 어떤 관계인지, 어떻게 생성되는지
- 사전 프롬프트 가이드(네거티브 키워드 등), 결과물 공유 기능의 진입점을 찾지 못했다 — 범위에서 제외된 것인지 아직 구현 전인지 불명
- 이미지·영상 생성 요청(POST) 엔드포인트, 라이브러리 삭제·찜 토글 API의 정확한 경로와 응답 스키마
- 로그인/회원가입/영상 생성/역프롬프트/라이브러리 삭제의 세부 인수 조건 다수(각 절에 [ ] 표기로 남겨둠) — 이번 검증은 화면 존재와 핵심 흐름 위주였고, 항목 하나하나를 전부 실행해 재현하지는 못했다
