## UC-IMAGE-01. 캐릭터·배경 이미지 생성

| 항목 | 내용 |
|------|------|
| 유즈케이스명 | 캐릭터·배경 이미지 생성 |
| 유즈케이스 ID | UC-IMAGE-01 |
| 주 액터 | 방송 PD/AD — 방송 프로그램 기획·제작 실무자. 포토샵 등 전문 디자인 툴이나 프롬프트 엔지니어링에 익숙하지 않음. 여러 프로그램을 동시에 맡는 경우가 많아 결과물을 하나하나 다듬기보다 촬영 전 짧은 시간 안에 캐릭터·배경의 대략적인 방향을 빠르게 잡아보고 싶어 함 |
| 목표 | 간단한 한 줄 프롬프트로 캐릭터·배경의 초기 형태를 빠르게 확인한다 |
| 사전조건 | 로그인 상태일 것 / 이미지 생성 화면에서 "캐릭터" 또는 "배경" 유형을 선택해 있을 것 |
| 사후조건 | 결과 이미지가 결과 영역에 표시되고, 생성과 동시에 라이브러리에 자동 저장됨 |
| 우선순위 | P0 |

**기본 흐름**
1. 사용자가 이미지 생성 화면에서 "캐릭터" 또는 "배경" 유형 탭을 선택한다 (캐릭터 유형은 각도를 단일/다각도 중에서 추가로 고를 수 있다)
2. 프롬프트 입력창에 캐릭터 또는 배경에 대한 간단한 설명을 입력한다 (한국어/영어 자유)
3. 비율(1:1/16:9/9:16 중 선택, 기본 1:1)과 품질(표준/4K 중 선택)을 고른다. 참고할 레퍼런스 이미지가 있다면 최대 8장까지 첨부할 수 있다
4. [생성] 클릭 또는 Enter
5. 시스템이 이미지를 생성한다 — 이 구간은 스피너/스켈레톤 + "이미지를 생성하고 있습니다…" 문구로 대기 상태를 명확히 알려준다(막연한 로딩만 보여주면 사용자가 멈춘 것으로 오인할 수 있음)
6. 결과가 결과 영역에 표시됨과 동시에 **별도 조작 없이 라이브러리에 자동 저장**된다
7. 사용자가 결과를 확인하고, 마음에 들면 [찜하기(하트)]로 즐겨찾기 표시하거나(UC-LIBRARY-03), 결과를 참고해 캐릭터시트 생성(UC-IMAGE-02)으로 넘어간다

**대안/예외 흐름**
- 프롬프트가 빈값이면 [생성]이 비활성화 상태로 유지된다
- 생성 실패 시 에러 메시지와 [다시 시도]가 표시되고, 클릭 시 동일 입력값으로 재요청한다
- 결과를 클릭하면 라이브러리 상세보기와 동일한 우측 패널이 열려 [재편집]·[동영상 만들기]·[다운로드]·[삭제]를 바로 쓸 수 있다

## UC-IMAGE-02. 캐릭터시트 생성

| 항목 | 내용 |
|------|------|
| 유즈케이스명 | 캐릭터시트 생성 |
| 유즈케이스 ID | UC-IMAGE-02 |
| 주 액터 | 방송 PD/AD — 캐릭터·배경 생성(UC-IMAGE-01)으로 방향을 대략 잡은 뒤, 실제 촬영·제작 회의에 바로 쓸 수 있는 완성도 있는 캐릭터 자료가 필요한 실무자. 디자이너에게 의뢰할 시간 여유는 없지만, 표정·소품·컬러까지 구체적으로 정리된 레퍼런스가 있어야 다른 팀원(연출·미술)과 소통이 원활하다고 느낌 |
| 목표 | 캐릭터 생성에서 확인한 외형을 바탕으로, 실제 제작에 쓸 완성도 높은 캐릭터 시트를 만든다 |
| 사전조건 | 로그인 상태일 것 / 이미지 생성 화면에서 "캐릭터시트" 유형을 선택해 있을 것 |
| 사후조건 | 캐릭터시트 이미지가 결과 영역에 표시되고, 생성과 동시에 라이브러리에 자동 저장됨 |
| 우선순위 | P0 |

**기본 흐름**
1. 사용자가 이미지 생성 화면에서 "캐릭터시트" 유형 탭을 선택한다
2. **[+ 캐릭터 만들기]** 버튼을 눌러 상세 입력 단계로 진입한다
3. 프롬프트와 옵션을 입력한다 — 진입 이후 상세 입력 방식(자유 텍스트 서술 vs 속성 선택 사이드바)은 이번 인수인계 검증에서 끝까지 확인하지 못했다. 리서치 당시 자료 기준으로는 파트1 캐릭터 기본~파트5 의상·악세서리로 구성된 속성 사이드바와 자유 텍스트 입력을 모두 지원하도록 계획되어 있었다
4. [생성] 클릭
5. 시스템이 캐릭터시트(턴어라운드+표정+소품+컬러 팔레트로 구성된 것으로 추정)를 생성한다
6. 결과가 결과 영역에 표시됨과 동시에 **별도 조작 없이 라이브러리에 자동 저장**된다
7. 사용자가 결과를 확인한다 — 이후 영상 생성(UC-VIDEO-01)에서 이 캐릭터를 스토리보드 제작에 참고하거나, 마음에 들면 [찜하기(하트)]로 즐겨찾기 표시 가능(UC-LIBRARY-03)

**대안/예외 흐름**
- 프롬프트가 빈값이거나 필수 항목 미입력 시 [생성] 비활성화
- 생성 실패 시 UC-IMAGE-01과 동일한 에러 처리

## UC-PROMPT-01. AI 프롬프트 변환 토글 사용

| 항목 | 내용 |
|------|------|
| 유즈케이스명 | AI 프롬프트 변환 토글 사용 |
| 유즈케이스 ID | UC-PROMPT-01 |
| 주 액터 | 방송 PD/AD — 원하는 장면을 한국어로는 구체적으로 설명할 수 있지만, 영어 프롬프트 작성 경험이 거의 없어 이를 AI가 잘 이해하는 구조(구도·조명·스타일 키워드 등)로 바꾸는 데는 서투름. 별도로 프롬프트 작성법을 배울 여유는 없음 |
| 목표 | 한국어로 입력해도 AI가 이미지 생성에 최적화된 영어 프롬프트로 바꿔주도록 해, 프롬프트 엔지니어링 지식 없이도 생성 품질을 확보한다 |
| 사전조건 | 이미지 생성 화면(캐릭터/배경/캐릭터시트 어느 유형이든)에서 프롬프트 입력창에 텍스트가 입력되어 있을 것 |
| 사후조건 | 저장된 결과의 프롬프트 메타데이터가 변환 On 시 변환된 영문 프롬프트 기준으로 기록됨 |
| 우선순위 | P1 |

**기본 흐름**
1. 사용자가 프롬프트 입력창에 한국어로 원하는 장면·캐릭터를 입력한다
2. "AI 프롬프트 변환" 토글을 On으로 켠다 (보조문구: "입력한 내용을 이미지 생성용 영어 프롬프트로 다듬어드려요")
3. [생성] 클릭 또는 Enter
4. 시스템이 백그라운드에서 Claude Sonnet으로 입력을 영어로 변환한다 — **변환된 영어 프롬프트는 화면에 노출하지 않는다**
5. 변환된 프롬프트로 바로 이미지 생성이 진행된다
6. 결과가 결과 영역에 표시된다

**대안/예외 흐름**
- 토글이 Off 상태(기본값)면 입력한 텍스트를 그대로 생성 요청에 사용한다

## UC-VIDEO-01. 영상 생성

| 항목 | 내용 |
|------|------|
| 유즈케이스명 | 영상 생성 |
| 유즈케이스 ID | UC-VIDEO-01 |
| 주 액터 | 방송 PD — 프로그램 연출·기획을 총괄하며, 실제 촬영에 들어가기 전 장면의 톤·구도·움직임을 미리 확인하고 싶어 함. AI 영상 생성 툴 사용 경험은 많지 않고, 팀 예산을 직접 관리하는 경우가 많아 생성 비용에 민감함 |
| 목표 | 스토리보드 이미지와 영상 프롬프트로 짧은 영상 클립을 생성해 실제 촬영 전 장면을 미리 확인한다 |
| 사전조건 | 로그인 상태일 것 / 영상 생성 화면에 진입해 있을 것 / 스토리보드 이미지 1장을 보유하고 있을 것 |
| 사후조건 | 생성된 영상이 결과 영역에 표시되고, 완료와 동시에 라이브러리에 자동 저장됨 |
| 우선순위 | P0 |

**기본 흐름**
1. 사용자가 영상 생성 화면에서 모델을 고른다 — **Seedance 2.0 / Kling 3.0**, 어느 쪽을 골라도 스토리보드 기반 영상 생성 용도로 쓸 수 있다(용도 구분 없음)
2. 선택한 모델에 맞춰 길이·비율·품질·레퍼런스 옵션이 바뀐다 (아래 표 참고)
3. 스토리보드 이미지 1장을 업로드한다 (필수). 필요하면 레퍼런스 이미지도 추가로 첨부한다(선택, 최대 개수는 모델별로 다름)
4. 영상 프롬프트를 입력한다
5. [생성] 클릭
6. 시스템이 요청을 접수하고 상태를 대기 중 → 생성 중 → 완료(또는 실패)로 표시한다. 영상은 이미지보다 훨씬 오래 걸리므로, 화면 이탈 시에도 서버 측 생성·자동 저장은 계속 진행된다
7. 생성 완료 시 인라인 비디오 플레이어로 결과가 표시됨과 동시에 **별도 조작 없이 라이브러리에 자동 저장**된다
8. 마음에 들면 [찜하기(하트)]로 즐겨찾기 표시 가능(UC-LIBRARY-03)

**모델별 옵션 (확인됨, 2026-08-02 실서비스 기준)**

| 옵션 | Seedance 2.0 | Kling 3.0 |
|------|------|------|
| 길이 | 4·5(기본)·8·10·15초·자동 | 3·4·5(기본)·8·10·15초 |
| 비율 | 16:9(기본)·9:16·1:1·21:9·4:3·3:4·자동 | 16:9(기본)·9:16·1:1 |
| 품질 | 고화질 1920×1080(기본)·표준 1280×720·480p·4K | 선택 옵션 없음(원인 불명, 재확인 필요) |
| 레퍼런스 최대 | 9장 | 4장 |

> 리서치 당시(옵션값 확정 문서) 정리했던 모델별 단가·해상도 비교(Kling $0.084/초, Seedance 720p $0.3034/초 등)와 3x3 그리드 슬라이스·시작/끝 프레임 지정 같은 처리 방식은 그 시점의 fal.ai 공식 확인·BE 테스트 자료였다. 지금 화면에서 확인되는 입력은 "스토리보드 이미지 1장 업로드"로 단순화되어 있고, 그 이후 내부적으로 모델별로 어떻게 처리하는지는 이번 검증 범위 밖이다 — 단가·내부 처리 방식이 궁금하면 최신 fal.ai 대시보드·BE 코드로 재확인이 필요하다.

**대안/예외 흐름**
- 프롬프트가 빈값이거나 스토리보드 이미지가 없으면 [생성] 비활성화
- 상태가 실패면 에러 메시지 + [다시 시도], 이전 입력값은 유지
- 오디오 포함 여부는 화면에서 별도 토글을 확인하지 못했다 — 상시 포함인지는 재확인 필요

## UC-VIDEO-02. 영상 재생성

## UC-LIBRARY-02. 라이브러리 상세보기·다운로드·삭제

| 목표 | 저장된 생성물을 크게 확인하고, 필요하면 다운로드하거나 더 이상 필요 없는 항목을 정리한다 |
| 사전조건 | 라이브러리 화면에 생성물이 1개 이상 표시되어 있을 것 (UC-LIBRARY-01 이후) |
| 사후조건 | 다운로드된 파일이 로컬에 저장되거나, 삭제된 항목이 라이브러리에서 사라진 상태 |
| 우선순위 | P0 |

1. 사용자가 그리드에서 항목을 클릭한다
2. **항목 타입에 따라 다른 상세보기가 열린다** — 이미지는 그리드가 그대로 보이는 채로 옆에 펼쳐지는 우측 패널, 영상은 그리드를 가리는 풀스크린 모달
3. 원본 이미지/영상, 생성 당시 프롬프트, 메타 정보(모델·품질·비율·생성일시, 영상은 작업 ID까지)가 표시된다
4. [다운로드] 클릭 시 원본 파일이 브라우저로 저장된다
5. 이미지 상세에는 [재편집]·[동영상 만들기]·[삭제]가, 영상 상세(모달)에는 찜하기(하트)·공유·[재편집]이 함께 있다
6. 더 이상 필요 없는 이미지 항목은 [삭제] 클릭으로 정리한다

**대안/예외 흐름**
- 다운로드 실패 시 인라인 에러 메시지와 함께 재시도 가능

## UC-LIBRARY-03. 찜하기(즐겨찾기) 토글

| 항목 | 내용 |
|------|------|
| 유즈케이스명 | 찜하기(즐겨찾기) 토글 |
| 유즈케이스 ID | UC-LIBRARY-03 |
| 주 액터 | 방송 PD/AD — 테스트 삼아 여러 번 생성하다 보니 라이브러리에 결과물이 빠르게 쌓여, 그중 실제로 마음에 들어 다시 쓸 것들과 그냥 시도해본 것들을 구분하고 싶어 함 |
| 목표 | 모든 생성 결과가 예외 없이 자동 저장되어 라이브러리가 계속 쌓이므로, 마음에 드는 항목만 따로 표시해 빠르게 다시 찾을 수 있게 한다 |
| 사전조건 | 생성 결과 화면 또는 라이브러리에 항목이 존재할 것 |
| 사후조건 | 해당 항목의 찜 상태가 토글되고, 라이브러리의 "찜한 목록" 세그먼트에 즉시 반영됨 |
| 우선순위 | P1 |

**기본 흐름**
1. 사용자가 영상 결과 화면 또는 라이브러리 영상 상세 모달에서 하트 아이콘을 클릭한다
2. 시스템이 즉시 하트 아이콘 상태를 바꾼다
3. 라이브러리 상단 "찜한 목록" 세그먼트에도 바로 반영된다
4. 다시 클릭하면 찜이 해제된다

**대안/예외 흐름**
- **이미지 결과·이미지 상세 패널에서 하트 아이콘을 확인하지 못했다** — 영상 쪽에만 있는 것인지, 이미지에도 있는데 놓친 것인지는 재확인이 필요하다
- 찜은 저장 액션이 아니므로, 찜을 해제해도 라이브러리에서 항목이 사라지지 않는다(삭제는 별도 액션, UC-LIBRARY-02)

## UC-REVERSE-01. 역프롬프트 — 업로드→추출→수정→재생성

| 항목 | 내용 |
|------|------|
| 유즈케이스명 | 역프롬프트 — 업로드→추출→수정→재생성 |
| 유즈케이스 ID | UC-REVERSE-01 |
| 주 액터 | 방송 PD — 레퍼런스가 될 만한 이미지(다른 프로그램 스틸컷, 무드보드 등)는 자주 접하지만, 그 스타일을 말로 옮겨 프롬프트를 처음부터 작성하는 건 부담스러워 함. "이거랑 비슷하게" 정도의 직관적인 재현을 원함 |
| 목표 | 마음에 드는 레퍼런스 이미지 하나로, 비슷한 스타일의 새 이미지를 빠르게 재현한다 |
| 사전조건 | 로그인 상태일 것 / 역프롬프트 화면에 진입해 있을 것 / 참고할 레퍼런스 이미지 파일을 보유하고 있을 것 |
| 사후조건 | [이 프롬프트로 생성하기]를 실행했다면, 재생성된 새 이미지가 라이브러리에 자동 저장된 상태. **추출만 한 상태로는 아무것도 저장되지 않는다** |
| 우선순위 | P2 |

**기본 흐름**
1. 사용자가 레퍼런스 이미지를 업로드한다 (역프롬프트 비율도 auto/1:1/16:9/9:16 중에서 미리 골라둘 수 있다)
2. [프롬프트 생성] 클릭
3. 시스템(Claude Sonnet 5)이 이미지를 분석해 "제안된 프롬프트" 패널에 결과를 표시한다
4. 사용자가 [복사]로 프롬프트를 클립보드에 복사하거나, 더보기(⋮) 아이콘을 눌러 다음 두 가지를 선택한다
   - **[수정]** — 프롬프트 텍스트와 비율을 함께 고쳐서 원하는 방향으로 다듬는다
   - **[이 프롬프트로 생성하기]** — 이 프롬프트로 바로 이미지 생성을 실행한다
5. [이 프롬프트로 생성하기]를 실행하면 새 이미지가 생성되고, **그 결과만** 라이브러리에 자동 저장된다

**대안/예외 흐름**
- 분석 실패 시 에러 메시지 + [다시 시도] (업로드 파일은 유지)
- 스타일·조명·구도·렌즈·색감·분위기 같은 분석 태그가 결과에 별도로 표시되는지는 이번 검증에서 실제 추출을 실행해보지 않아 확인하지 못했다(비용 문제)
- 프롬프트를 추출만 하고 [이 프롬프트로 생성하기]를 누르지 않으면, 화면을 벗어나는 순간 그 프롬프트는 저장되지 않고 사라진다

## 확인되지 않은 사항

- 캐릭터시트 유형 [+ 캐릭터 만들기] 진입 이후 상세 입력 화면 구성(자유 텍스트 vs 속성 선택 사이드바)
- Kling 3.0에 품질 선택 옵션이 없는 이유
- 영상 오디오 포함 여부의 UI 노출 방식
- 역프롬프트 결과의 분석 태그(스타일/조명/구도/렌즈/색감/분위기) 실제 노출 여부
- 이미지 결과·라이브러리 이미지 상세에 찜하기(하트) 아이콘이 있는지
- 라이브러리 영상 상세 모달의 [삭제] 버튼 위치
- 모델별 실제 처리 방식·최신 단가 (리서치 당시 자료는 참고용으로만 남김, 6장 참고)
