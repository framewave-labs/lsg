## 1. 제품 개요

### 1.1 서비스명

**GeNova** (제노바) — KX 엔터테인먼트(본사) 지정 서비스명, 2026-07-20(월) 수령. 그 전까지는 팀 내부 브레인스토밍으로 정한 임시명 `KX GenStudio`를 썼다. 최종 발표 자료와 대외 표기는 모두 `GeNova` 기준이다.

### 1.2 한 줄 정의

아이디어를 이미지와 짧은 영상으로 구체화할 수 있도록, 이미지 생성·영상 생성·역프롬프트·미디어 라이브러리를 연결한 웹 기반 생성형 AI 제작 서비스

### 1.3 서비스 설명

GeNova는 방송 제작자·콘텐츠 기획자가 복잡한 편집 프로그램이나 프롬프트 작성법을 몰라도, 화면 흐름을 따라가는 것만으로 캐릭터·배경 이미지와 짧은 영상 결과물을 만들 수 있도록 돕는 서비스다. 기획 초기엔 이미지 생성·저장·조회 흐름을 먼저 안정화한 뒤 영상 생성으로 확장하는 단계별 목표로 진행됐고, 인수인계 시점 기준으로 이미지 생성·영상 생성·역프롬프트·미디어 라이브러리·인증·프로필 흐름이 모두 실 서비스에 구현되어 있다.

```text
홈 진입
→ 이미지 생성 (캐릭터 / 배경 / 캐릭터시트)
→ 생성 결과 확인 (자동으로 라이브러리에 저장됨)
→ 라이브러리 조회
→ 영상 생성 (스토리보드 이미지 업로드 + 프롬프트)
→ 진행 상태 조회
→ 영상 결과 확인 (자동 저장)
→ 필요 시 역프롬프트로 레퍼런스 이미지에서 프롬프트 역추출 → 재생성
```

### 1.4 문제 정의

| 문제 | 설명 |
|------|------|
| 생성 흐름 분산 | 이미지 생성, 영상 생성, 프롬프트 정리, 결과물 저장이 서로 다른 도구에 흩어져 있다 |
| 프롬프트 작성 부담 | 사용자는 장면 의도는 있어도 AI 프롬프트 구조에 익숙하지 않다 |
| 결과물 관리 어려움 | 생성물이 누적되면 다시 찾고 비교하기 어렵다 |
| 시각 일관성 부족 | 캐릭터·배경·영상 결과가 같은 기준으로 이어지지 않을 수 있다 |
| 영상 생성 비용 리스크 | 영상 생성은 실패 호출과 긴 옵션에서 비용 부담이 빠르게 커진다 |
| 비동기 상태 이해 어려움 | 영상 생성처럼 시간이 걸리는 작업은 대기·처리·성공·실패 상태를 명확히 보여줘야 한다 |

### 1.5 대상 사용자

| 사용자 | 핵심 니즈 |
|------|------|
| 방송 PD / AD | 촬영 전 짧은 시간 안에 캐릭터·배경의 대략적인 방향을 빠르게 잡아보고 싶다 |
| 영상 제작 경험이 적은 사용자 | 복잡한 편집 도구 없이 아이디어를 이미지와 영상으로 만들어보고 싶다 |
| 학생 / 발표 준비자 | 과제나 발표에 쓸 시각 자료와 짧은 영상 초안을 빠르게 만들고 싶다 |
| 개인 창작자 / 소규모 팀 | 캐릭터·배경·장면 이미지의 일관성을 유지하며 콘텐츠 초안을 만들고 싶다 |
| 방송 / 콘텐츠 기획자 | 기획 단계에서 회의용 이미지와 영상 레퍼런스를 빠르게 확인하고 싶다 |

## 3. 주요 사용자 흐름 (실제 구현 기준)

### 3.1 이미지 생성 흐름

```text
이미지 생성 화면 진입
→ 유형 선택: 캐릭터 / 배경 / 캐릭터시트
→ 프롬프트 입력 (+선택: AI 프롬프트 변환, 레퍼런스 이미지 최대 8장)
→ 옵션 선택: 비율 · 품질 · 수량
→ 생성 요청
→ 결과 확인 (자동으로 라이브러리에 저장됨 — 별도 저장 버튼 없음)
→ 상세 패널에서 재편집 / 영상 만들기 / 다운로드
```

### 3.2 영상 생성 흐름

```text
영상 생성 화면 진입
→ 모델 선택: Seedance 2.0 / Kling 3.0 (모델에 따라 옵션이 전부 다름)
→ 스토리보드 이미지 업로드(필수) + 레퍼런스 이미지(선택)
→ 영상 프롬프트 입력
→ 길이 · 비율 · 품질(모델별 상이) 옵션 선택
→ 영상 생성 요청
→ 진행 상태 조회(5초 간격 폴링, 최대 15분)
→ 결과 확인 (자동 저장)
```

### 3.3 라이브러리 흐름

```text
라이브러리 진입
→ 내 작업 / 찜한 목록 세그먼트, 전체 · 이미지 · 영상 필터, 최신순 · 오래된순 정렬
→ 항목 클릭 → 상세 오버레이(이미지 · 영상 공통 컴포넌트)
→ 재편집 / (이미지만) 영상 만들기 / 다운로드
→ 삭제 · 찜은 그리드 카드에 마우스를 올렸을 때 나오는 액션바에서
```

### 3.4 역프롬프트 흐름

```text
역프롬프트 화면 진입
→ 이미지 업로드 (PNG·JPG·WEBP, 50MB 이하)
→ 비율 선택 (auto/1:1/16:9/9:16)
→ 프롬프트 생성 요청
→ 결과 확인 → [복사] 또는 더보기(⋮) → [수정](프롬프트+비율) / [이 프롬프트로 이미지 생성]
→ 실제 이미지 생성까지 완료해야 라이브러리에 저장됨 (추출만으로는 저장되지 않음)
```

## 4. 화면별 요구사항 (확인 기준)

### 4.1 인증

- 이메일 회원가입(이메일→닉네임→비밀번호 3단계 마법사) + 로그인, Google OAuth 병행
- 통합 PRD 15장은 "인증/권한 MVP 범위"를 후속 확인 항목으로 남겨뒀었는데, 최종적으로는 포함하는 쪽으로 정리됐다
- Google 계정이 이미 이메일로 가입된 계정과 충돌하면 자동 연동 없이 에러로 거부된다(백엔드 소스 확인됨)

### 4.2 이미지 생성

| 항목 | 내용 |
|------|------|
| 모델 | GPT Image 2.0 (OpenAI 직접 호출) |
| 생성 목적(유형) | 캐릭터 / 배경 / 캐릭터시트 — 통합 PRD의 "캐릭터, 배경, 키이미지"에서 "키이미지"가 "캐릭터시트"로 이름이 정리됐다. 캐릭터시트는 `purpose` 파라미터가 아니라 완전히 별도인 `character-concept-sheet` 엔드포인트로 구현돼 있다 |
| 옵션 | 비율(1024x1024/1536x864/864x1536/auto), 품질(standard/high), 수량(1~4장), 레퍼런스 이미지(최대 8장, 통합 PRD엔 없던 기능) |
| 후속 행동 | 자동 저장, 재편집, 동영상 만들기, 다운로드 (삭제는 라이브러리 그리드에서) |

### 4.3 영상 생성

| 항목 | 내용 |
|------|------|
| 모델 | Seedance 2.0 / Kling 3.0 (fal.ai 경유) — 모델에 따라 길이·비율·품질·레퍼런스 최대 개수가 전부 다름 |
| 입력 | 스토리보드 이미지 1장(필수) + 레퍼런스 이미지(선택) — 통합 PRD의 "3x3 스토리보드 이미지 1장 업로드"와 일치 |
| 상태 표시 | 대기(IN_QUEUE)/진행(IN_PROGRESS)/완료(COMPLETED)/실패(ERROR) — 통합 PRD 기준 상태값(`RUNNING`/`SUCCESS`/`FAILED`, `PENDING` 없음)과는 명칭이 다르게 최종 구현됐다 |
| 오디오 | 토글 없이 항상 포함(`generate_audio: true` 하드코딩, 프런트 소스 확인됨) |
| 후속 행동 | 자동 저장, 재편집, 다운로드 |

### 4.4 미디어 라이브러리

- 전체/이미지/영상 필터, 최신순/오래된순 정렬, 내 작업/찜한 목록 세그먼트
- 상세보기는 이미지·영상 모두 **동일한 오버레이 컴포넌트**를 쓴다 — 과거 "이미지=우측 패널/영상=풀스크린 모달로 서로 다르다"고 파악했던 것은 오기였다(프런트 소스 확인됨)
- 통합 PRD 15장이 "라이브러리 좋아요/찜하기 처리 방식(필터 or 별도 기능)"을 후속 확인 항목으로 남겼는데, 실제로는 상단 "찜한 목록" 세그먼트 + 그리드/상세 하트 아이콘으로 구현됐다

### 4.5 역프롬프트

- Claude Sonnet 5, 비율 선택(auto/1:1/16:9/9:16) 포함
- 결과 화면은 [복사] + 더보기(⋮) 메뉴 안에 [수정]·[이 프롬프트로 이미지 생성] — 추출만으로는 라이브러리에 저장되지 않고, 생성까지 실행해야 저장된다
- 스타일·조명·구도·렌즈·색감·분위기 분석 태그는 실제로 노출되지 않는다(2026-08-02 실행 확인됨)

### 4.6 내 프로필

- 통합 PRD 8절 화면 구조엔 "내 프로필/설정"이 3순위로만 언급되고 세부 요구사항은 없었다
- 실제로는 프로필/활동/위험구역 3개 카드로 구성. 스튜디오 이름(백엔드 `nickname` 필드), 프로필 이미지, 회원 탈퇴(브라우저 기본 확인창) 포함

## 5. API 및 데이터 저장 기준

통합 PRD 10장은 `MediaFile`/`GenerateJob` 테이블과 `/api/generate-image`, `/api/generate-video`, `/api/video-status`, `/api/file` 계열 API를 기준으로 제시했다. `kx-frontend` 소스코드로 확인한 실제 경로는 아래와 같이 다르다.

| 구분 | 실제 확인된 경로 |
|------|------|
| 인증 | `POST /api/auth/signup`, `POST /api/auth/login`, `POST /api/auth/logout`, `POST /api/auth/reissue`, `GET /api/auth/email/check`, `GET /oauth2/authorization/google` |
| 이미지 생성 | `POST /api/generate/images`, `POST /api/generate/images/character-concept-sheet`, `GET /api/generate/images/jobs/{jobId}`, `GET /api/generate/images/jobs/active` |
| 영상 생성 | `POST /api/generate/videos`, `GET /api/generate/videos/jobs/{jobId}`, `GET /api/generate/videos/jobs/active` |
| 역프롬프트 | `POST /api/generate/reverse-prompt`, `PATCH /api/generate/reverse-prompt/{id}`, `POST /api/generate/reverse-prompt/{id}/generate` |
| 파일/미디어 | `POST /api/media/images/upload`, `GET /api/media/files`, `GET /api/media/files/recent`, `GET /api/media/images/{id}/download`, `GET /api/media/files/{id}/download-url`, `DELETE /api/media/files/{id}`, `POST`/`DELETE /api/media/files/{id}/favorite` |

| 사용자 | `GET/PATCH /api/me/profile`, `POST/DELETE /api/me/profile-image`, `GET /api/me/generation-summary`, `DELETE /api/me` |

**DB 기준**: `User`, `MediaFile`, `GenerateJob` 테이블 구조는 개발단이 정리한 `03_엔지니어링/2026-08-03_개발단_DB명세서_스냅샷.md`(원본, 개발 중 시점 스냅샷) 참고. 저장소는 AWS S3(EC2 IAM Role 권장)를 쓴다(담당 PM 확인).

## 8. 확인되지 않은 사항

`기능명세서_v8.0.md` §12와 동일 기준. 대부분의 항목은 2026-08-02~03 소스코드 확인과 실행 테스트로 해소됐고, 아래만 남아있다.

- 공유 링크: 백엔드 API·프런트 컴포넌트 일부(공유 아이콘)는 존재하나 실제 화면에서 연결돼 동작하는지는 담당 PM 확인 결과 아니라고 확인됨 — 어느 지점이 끊겨 있는지는 개발단 재확인 필요
- 캐릭터시트 상세 입력 화면의 실제 UI 노출 형태(컬러 팔레트 등)
- 역프롬프트 결과 프롬프트 "80단어 이하" 기준 준수 여부
- 라이브러리 삭제 확인 모달 유무, 삭제 후 그리드 즉시 반영 여부
- 찜 토글의 그리드/찜한 목록 실시간 동기화 여부
- 정식 도메인 연결 계획, AWS 개인 계정→회사 계정 이관 일정(`06_참고자료` 배포 이전 문서 참고)
