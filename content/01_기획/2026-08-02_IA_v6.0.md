# A2팀 IA — 인수인계본 v6.0
> 작성일: 2026-07-12 | 인수인계본 정리일: 2026-08-02 | 작성자: 이슬기 (PM)
> GeNova 전체 화면 구조를 실제 배포 서비스(`kx-frontend-azure.vercel.app`) 기준으로 정리한 문서다. v5.0의 화면 트리 구조에, `kx-frontend`(main 브랜치) 소스코드 확인 결과와 실 계정으로 역프롬프트를 직접 실행한 결과를 반영했다. 더 긴 서술(에러 처리, 인수 조건 등)은 `2026-08-02_기능명세서_v8.0.md` 쪽이 원본이며, 여기서는 트리 구조에 붙는 수준으로만 압축했다. 엑셀본은 `2026-08-02_생성형AI통합엔진_A2_IA_v8.xlsx` 참고.
> "확인됨" · "백엔드 소스 확인됨" · "프런트 소스 확인됨" · "실행 확인됨" · "설계 당시 사양(재확인 필요)"을 구분해 표기했다.

## 전체 구조

```
비로그인
├── 홈 (랜딩) — 히어로 + 원터치 프롬프트 입력바
├── 로그인
│   ├── 이메일/비밀번호 — 실패 시 AUTH_004 "이메일 또는 비밀번호가 올바르지 않습니다"(가입 여부 구분 없음, 백엔드 소스 확인됨)
│   └── 구글 계정으로 시작하기 — Google OAuth, 콜백 kx-studio.duckdns.org/login/oauth2/code/google
│       └── 이미 로컬 계정 있는 이메일로 시도 시 자동연동 없이 AUTH_005 409 충돌 에러(백엔드 소스 확인됨)
└── 회원가입 — 3단계 마법사, 순서는 **이메일(1) → 닉네임(2) → 비밀번호(3)**(프런트 소스 확인됨)
    ├── 1단계: 이메일 입력 — GET /api/auth/email/check?email= 호출 (확인됨)
    │   └── ⚠ 현재도 503 오류로 다음 단계 진행 불가 (2026-08-02 재확인, 인프라 이슈 지속)
    ├── 2단계: 닉네임 입력 — 이메일 칩 상단 노출, 빈 값이면 클라이언트 에러(프런트 소스 확인됨)
    ├── 3단계: 비밀번호+비밀번호 확인+약관 동의 체크박스 — **UI엔 비밀번호 확인 필드가 있으나 서버 전송 바디에는 안 실림**(프런트 소스 확인됨)
    └── 실제 API 페이로드: 이메일(최대100자)·비밀번호(8~100자)·닉네임(최대50자) — 백엔드 소스 확인됨
        └── 가입 성공 → fetchMe() → 즉시 인증 상태 전환 → /home 이동 (로그인 화면 거치지 않음, 프런트 소스 확인됨)

로그인 후
├── 사이드바 (전 화면 공통)
│   ├── 기본: 아이콘만 노출
│   ├── hover 시 확장: 라벨 + 워드마크 + 하단 프로필(이름·이메일) + [로그아웃]
│   └── 메뉴: 홈 · 이미지 · 영상 · 역프롬프트 · 라이브러리

│   ├── 히어로 — 카피 "한계없는 상상을, 현실로" + 모델 배지(GPT Image 2.0/Seedance 2.0·Kling 3.0) + 원터치 입력바
│   └── 탐색하기 — 큐레이션 갤러리(유저 발행 아님) · 이미지/영상 탭 · 해시태그 필터 · API: GET /api/media/files/recent(프런트 소스 확인됨)
│
├── 이미지 생성 화면 — 모델 GPT Image 2.0 고정
│   ├── 유형: 캐릭터 — POST /api/generate/images (purpose=CHARACTER) · 각도(단일/다각도=multiViewEnabled) · 결과: 단일 1장 또는 다각도 세트(추정)

│   ├── 공통 옵션(백엔드 소스 확인됨) — size(auto/1024x1024/1536x864/864x1536) · quality(standard/high, 화면상 "4K"는 high로 추정) · imageCount(1~4장) · 레퍼런스(최대 8, 화면상 확인) · promptCorrectionEnabled(AI 프롬프트 변환 On/Off)

│   └── 결과 → MediaDetailPanel(라이브러리와 공통 컴포넌트, 10절 참고)
│       ├── [재편집] · [영상 만들기] · [다운로드](PNG, image_{YYYYMMDD}_{HHmmss}.png)
│       └── [재생성] — 기존 항목 유지, 새 결과 별도 저장. 삭제는 상세보기가 아니라 그리드 카드 hover 액션바에서(10절 참고)
│
├── 영상 생성 화면
│   ├── 모델: Seedance 2.0 — 길이(4/5/8/10/15초/자동) · 비율(16:9/9:16/1:1/21:9/4:3/3:4/자동) · 품질(고화질1920×1080/표준1280×720/480p/4K) · 레퍼런스 최대 9장
│   ├── 모델: Kling 3.0 — 길이(3/4/5/8/10/15초) · 비율(16:9/9:16/1:1) · **품질 옵션 없음 — 프런트 `MODEL_CAPABILITIES`에 의도적으로 비워둔 것(프런트 소스 확인됨, 백엔드 제약 아님 확정)** · 레퍼런스 최대 4장
│   ├── 요청: POST /api/generate/videos — startMediaFileId · endMediaFileId · referenceMediaFileIds(최대9) · modelId · prompt · options{duration, generate_audio:true(항상 true, 프런트 소스 확인됨), aspect_ratio?, resolution?}

│   ├── 작업 상태 폴링 — GET /api/generate/videos/jobs/{jobId}, GET /api/generate/videos/jobs/active(프런트 소스 확인됨), 5초 간격·최대 15분(900,000ms) 타임아웃
│   ├── **오디오 — 무조건 포함, 토글 없음 (담당 PM 확인 + 프런트 소스 확인됨, `generate_audio: true` 하드코딩)**

│   │   ├── [복사]
```

## 에러 코드 체계 (백엔드 소스 확인됨 — `global.exception.ErrorCode`)

실제 에러 코드는 `COMMON_001~006,999` / `AUTH_001~006` / `GENERATE_001` 14개뿐이다(백엔드 소스 확인됨). 전체 표는 `기능명세서_v8.0.md` 3.2절 참고. 특히 이미지 생성·영상 생성·역프롬프트 분석 실패가 전부 `GENERATE_001` 하나로 통합되어 있다는 점, 파일 업로드 형식/용량 오류가 전부 `COMMON_001`(메시지만 다름)이라는 점이 프런트 에러 분기 로직 인수인계 시 중요하다.

## 확인되지 않은 사항

**v5.0에서 프런트 소스 확인·실제 실행으로 해소된 항목**
- ~~회원가입 2·3단계 실제 화면 구성~~ → 이메일→닉네임→비밀번호 순서 확정, 비밀번호 확인 필드는 UI엔 있고 서버 전송엔 없음
- ~~"캐릭터시트"가 어떤 API·필드 구조로 구현돼 있는지~~ → 완전 별도 엔드포인트+구조화 속성 필드 방식(프런트 소스 확인됨)
- ~~찜하기(하트) 아이콘이 이미지 상세 패널에도 있는지~~ → 있음, 이미지·영상 공통
- ~~라이브러리 상세보기가 이미지·영상 타입별로 UI 구조가 다른지~~ → 동일 컴포넌트(MediaDetailPanel), 버튼 구성만 다름(프런트 소스 확인됨)
- ~~영상 오디오 상시 포함 여부·토글 유무~~ → 무조건 포함, 토글 없음(하드코딩 확정)
- ~~역프롬프트 분석 태그(6종) 실제 노출 여부~~ → 노출 안 됨(실행 확인됨)
- ~~`@my_studio` 핸들과 "스튜디오 이름"(닉네임) 필드의 관계~~ → 무관함. 핸들은 하드코딩된 목업 값
- ~~이미지·영상 생성 요청(POST), 라이브러리 삭제·찜 토글 API의 정확한 경로~~ → 전체 확정(위 트리 참고)

**여전히 남아있는 항목**
- 캐릭터시트 상세 입력 화면의 실제 UI 노출 형태(컬러 팔레트 등)
- 역프롬프트 결과 프롬프트 "80단어 이하" 기준 준수 여부 — 실행 결과 이보다 길 수 있음
- 라이브러리 삭제 확인 모달 유무, 삭제 후 그리드 즉시 반영 여부
- 찜 토글의 그리드/찜한 목록 실시간 동기화 여부
