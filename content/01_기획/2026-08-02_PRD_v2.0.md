# A2팀 PRD (Product Requirements Document) — 인수인계본 v2.0
> 작성일: 2026-06-25 | 인수인계본 정리일: 2026-08-02 | 작성자: 이슬기 (PM)
> 로컬 v1(2026-06-25, 킥오프 전 초안)은 이후 `framewave-docs` 통합 PRD(v1.2~v1.4, 손찬용 PM 정리)로 대체되어 실제로 쓰인 적이 없다. 이 v2.0은 통합 PRD를 기준으로 삼고, 2026-08-02 실 서비스 대조 검증(`2026-08-02_기능명세서_v4.0.md`, `2026-08-02_IA_v3.0.md`) 결과를 반영해 다시 정리한 최종본이다.
> **로컬 v1과 달랐던 점**: v1은 인증을 MVP 범위 밖으로 뒀고 Supabase 기반 데이터 모델과 Shot1~9 개별 세션 관리(F003-A) 기능을 전제로 작성됐다. 실제로는 인증(이메일+Google)이 포함됐고, 저장소는 AWS이며, Shot 세션 관리 기능은 만들어지지 않았다 — 이 부분은 v1 작성 이후 방향이 바뀐 것으로 보인다.

## 2. 실제 구현된 기능 범위

아래는 2026-08-02 실 서비스 확인 기준이다. 상세 사양은 `기능명세서_v4.0.md`를 참고.

| 기능 | 확인 상태 |
|------|---------|
| 인증(이메일 로그인·회원가입, Google OAuth) | 구현됨 — 회원가입은 이메일→2단계→3단계 마법사 구조(2·3단계는 이메일 확인 API 오류로 재확인 못함) |
| 이미지 생성 (유형: 캐릭터/배경/캐릭터시트) | 구현됨 |
| 영상 생성 (Seedance 2.0 / Kling 3.0, 모델별 옵션 상이) | 구현됨 |
| 역프롬프트 (이미지→프롬프트 추출→수정→재생성) | 구현됨 |
| 미디어 라이브러리 (이미지+영상 통합, 내 작업/찜한 목록) | 구현됨 |
| 내 프로필 (스튜디오 이름, 활동, 회원 탈퇴) | 구현됨 |
| 홈 화면 (히어로+원터치 생성+탐색하기 큐레이션) | 구현됨 |
| Shot1~9 개별 세션 관리·재생성 (로컬 PRD v1의 F003-A) | **만들어지지 않음** — 통합 PRD·실서비스 어디에도 이 개념이 없다. 영상 생성은 스토리보드 이미지 1장 업로드 방식으로 통일됨 |
| 방향별 레퍼런스를 별도 화면/탭으로 분리 (통합 PRD의 A001) | **별도 화면이 아니라 "유형" 탭(캐릭터/배경/캐릭터시트) 안에 흡수됨** — 통합 PRD 9.2절이 "이미지 생성 화면 안의 탭/섹션"으로 계획한 방향과 일치 |
| 사전 프롬프트 가이드 | 실서비스에서 진입점을 찾지 못함 — 통합 PRD 15장의 "후속 확인 항목"에서 답이 나지 않은 채로 남은 것으로 보임 |
| 공유 링크 기능 | 실서비스에서 진입점을 찾지 못함 — 위와 동일 |

## 3. 화면별 요구사항 (확인 기준)

### 3.1 인증

- 이메일 회원가입(3단계 마법사) + 로그인, Google OAuth 병행
- 통합 PRD 15장은 "인증 / 권한 MVP 범위"를 후속 확인 항목으로 남겨뒀었는데, 최종적으로는 포함하는 쪽으로 정리됐다

### 3.2 이미지 생성

| 항목 | 내용 |
|------|------|
| 모델 | GPT Image 2.0 (OpenAI 직접 호출 — fal.ai 경유 아님, 2026-07-28 QA에서 확인) |
| 생성 목적(유형) | 캐릭터 / 배경 / 캐릭터시트 — 통합 PRD의 "캐릭터, 배경, 키이미지"에서 "키이미지"가 "캐릭터시트"로 이름이 정리된 것으로 보인다 |
| 옵션 | 비율(1:1/16:9/9:16), 품질(표준/4K), 수량, 레퍼런스 이미지(최대 8장, 통합 PRD엔 없던 기능) |
| 후속 행동 | 자동 저장, 재편집, 동영상 만들기(신규), 다운로드, 삭제 |

### 3.3 영상 생성

| 항목 | 내용 |
|------|------|
| 모델 | Seedance 2.0 / Kling 3.0 (fal.ai 경유) — 모델에 따라 길이·비율·품질·레퍼런스 최대 개수가 전부 다름 |
| 입력 | 스토리보드 이미지 1장(필수) + 레퍼런스 이미지(선택) — 통합 PRD의 "3x3 스토리보드 이미지 1장 업로드"와 일치 |
| 상태 표시 | 대기/처리 중/완료/실패 — 통합 PRD 기준 상태값(`RUNNING`/`SUCCESS`/`FAILED`, `PENDING` 없음)과 화면 표시 문구가 일치하는지는 재확인 필요 |
| 후속 행동 | 자동 저장, 재편집, 다운로드 |

### 3.4 미디어 라이브러리

- 전체/이미지/영상 필터, 최신순/오래된순 정렬, 내 작업/찜한 목록 세그먼트
- 상세보기는 **이미지=우측 패널 / 영상=풀스크린 모달**로 타입에 따라 다르게 구현되어 있다 — 통합 PRD 7.4절은 이런 구분을 언급하지 않았다
- 통합 PRD 15장이 "라이브러리 좋아요/찜하기 처리 방식(필터 or 별도 기능)"을 후속 확인 항목으로 남겼는데, 실제로는 상단 "찜한 목록" 세그먼트 + 상세보기 내 하트 아이콘으로 구현됐다

### 3.5 역프롬프트

- Claude Sonnet 5, 비율 선택(auto/1:1/16:9/9:16) 포함
- 결과 화면은 [복사] + 더보기(⋮) 메뉴 안에 [수정]·[이 프롬프트로 생성하기] — 추출만으로는 라이브러리에 저장되지 않고, 생성까지 실행해야 저장된다

### 3.6 내 프로필

- 통합 PRD 8절 화면 구조엔 "내 프로필/설정"이 3순위로만 언급되고 세부 요구사항은 없었다
- 실제로는 프로필/활동/위험구역 3개 카드로 구성. 스튜디오 이름, 프로필 이미지, 회원 탈퇴(브라우저 기본 확인창) 포함

## 4. API 및 데이터 저장 기준

통합 PRD 10장은 `MediaFile`/`GenerateJob` 테이블과 `/api/generate-image`, `/api/generate-video`, `/api/video-status`, `/api/file` 계열 API를 기준으로 제시했다. 실제 네트워크 요청에서 아래 경로가 확인됐다 — 통합 PRD가 제시한 이름과 다르다.

| 통합 PRD 기준 | 실제 확인된 경로 |
|------|------|
| (인증 관련 언급 없음) | `GET /api/auth/email/check?email=` |
| (언급 없음) | `GET /api/me/profile` |
| `GET /api/file` (파일 목록) | `GET /api/media/files?type={IMAGE\|VIDEO}&page=&size=` |
| `GET /api/file/{id}/download` | `GET /api/media/images/{id}/download` |
| (언급 없음) | `GET /api/generate/images/jobs/active`, `GET /api/generate/videos/jobs/active` |

이미지·영상 생성을 요청하는 POST 엔드포인트의 정확한 경로는 확인하지 못했다. 로컬 PRD v1의 Supabase 스키마·Shot 세션 테이블은 실제로 쓰이지 않은 것으로 보인다(저장소는 AWS S3 또는 로컬 경로 — 통합 PRD 10.2절과 일치).

## 7. 확인되지 않은 사항

`기능명세서_v4.0.md`·`IA_v3.0.md`와 동일 기준.

- 회원가입 2·3단계 필드 구성 (이메일 확인 API 503으로 진행 불가)
- 캐릭터시트 [+ 캐릭터 만들기] 진입 이후 상세 화면 구성
- Kling 3.0 품질 옵션 부재 원인
- 영상 오디오 상시 포함 여부
- 역프롬프트 분석 태그(6종) 실제 노출 여부
- 라이브러리 상세보기 이미지=패널/영상=모달 차이가 의도된 설계인지
- `@my_studio` 형태의 회원 핸들과 "스튜디오 이름" 필드의 관계
- 이미지·영상 생성 요청(POST) 엔드포인트의 정확한 경로
