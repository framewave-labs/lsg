## 1. 현재 배포 구조

| 항목 | 내용 |
|------|------|
| 플랫폼 | Vercel (팀: KX-entertainment-A2) |
| 레포 | `KX-project-A2/kx-frontend` — `main` 브랜치 기준 자동 배포 |
| 현재 도메인 | `kx-frontend-azure.vercel.app` |
| 환경변수 | `VITE_API_BASE_URL` (Production/Preview 적용) — 현재 BE 임시 도메인(`https://kx-studio.duckdns.org`)을 가리키는 중 |

> 기능명세서 v5.0에서 확인한 백엔드 베이스 URL(`kx-studio.duckdns.org`)이 임시 동적 DNS라는 게 이 공유 내용으로 확인됨.

---

## 2. 정식 배포 전 확인·준비 필요한 것

### 2.1 Custom Domain 연결 여부

- 지금은 `vercel.app` 서브도메인 사용 중
- 정식 서비스 도메인(회사 소유 도메인)으로 연결할지 결정 필요
- 연결하려면: 도메인 구매/소유 확인 + DNS 설정 권한 필요

### 2.2 BE 인프라 이전 여부

- 지금 FE가 바라보는 BE 주소는 `kx-studio.duckdns.org`(임시 동적 DNS)
- **BE가 정식 도메인/인프라로 이전한다면** → FE의 `VITE_API_BASE_URL` 환경변수만 새 주소로 교체하면 됨(코드 변경 불필요)
- **BE가 그대로 duckdns를 유지한다면** → FE는 지금 상태 그대로 진행 가능

### 2.3 Vercel Production Checklist 잔여 항목

- [ ] Add Custom Domain (2.1과 연동)
- [ ] Enable Web Analytics
- [ ] Enable Speed Insights

필수는 아니지만, 정식 운영 전환 시 같이 켜두는 것을 권장.

---

## 3. 결론

**FE에서 별도로 필요한 절차는 없다.** 남은 결정 사항(커스텀 도메인 연결 여부, BE 인프라 이전 여부)은 회사 측(도메인 소유·DNS 권한 보유자, BE 인프라 담당자)의 결정을 기다리는 상태이며, 결정되는 대로 FE는 환경변수 교체만으로 대응 가능하다.
